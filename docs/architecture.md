# ADR 001: Native authenticated MCP proof of concept

Date: 2026-10-18. Status: initial proof of concept implemented; extended by [ADR 002](capabilities.md). Vessel and publication acceptance remain pending.

## Confirmed interfaces

The source review used Signal K master commit [`340d5bb`](https://github.com/SignalK/signalk-server/tree/340d5bb62c17ec58d2a3497dbbf081cd87af2a96), Container Manager [`7ed3f47`](https://github.com/dirkwa/signalk-container/tree/7ed3f478c5cb86d1ea7825b840e1742b5ce40f58), and VesselSense [`e04e7db`](https://github.com/VesselSense/signalk-mcp-server/tree/e04e7dba68b43a4e1c1534b03c0da6192d82ec9d). Integration tests use the separately pinned npm release `signalk-server@2.33.0`; a master checkout is not release compatibility evidence.

| Area                    | Evidence and decision                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Native routing          | `src/interfaces/plugins.ts` and `packages/server-api/src/plugin.ts` implement `router.access('readonly').post(...)`. Unclassified routes retain admin protection. Register only the MCP endpoint at readonly.                                                                                                                                                                                                                                                         |
| Authentication          | `src/tokensecurity.ts` verifies JWTs and resolves current user/device permissions. HTTP middleware can prefer a cookie over Authorization. The adapter calls `authorizeWS` with a fresh bearer-only connection on each request and tool call, preventing cookie identity substitution.                                                                                                                                                                                |
| Data authorization      | `getSelfPath` and `getPath` are unfiltered model accessors. `checkACL(identifier, 'vessels.self', path, source, 'read')` applies the server's configured path/source ACLs. Check before returning or listing a measurement. Never grant implicit admin privilege.                                                                                                                                                                                                     |
| Public API gap          | Security strategy hooks are not in the supported ServerAPI contract. Feature detection and release tests contain this dependency; a documented public bearer-authentication and read-authorization adapter would remove it. No Signal K core patch is required for this proof of concept.                                                                                                                                                                             |
| Feature discovery       | `src/api/discovery/index.ts` provides `/signalk/v2/features`; public ServerAPI includes `getFeatures`. This is feature/provider discovery, not a universal executable capability schema.                                                                                                                                                                                                                                                                              |
| Plugin OpenAPI          | Plugins expose `getOpenApi`; server internals collect documents through `getPluginOpenApi`/`getPluginOpenApiRecords`. No equivalent public ServerAPI getter was confirmed. Future discovery should use documented HTTP discovery or request a stable public interface.                                                                                                                                                                                                |
| Inter-plugin invocation | [PR #2881](https://github.com/SignalK/signalk-server/pull/2881) remains open. Its proposed `pluginFetch` uses a new readonly plugin principal, not the inbound user's identity. It does not satisfy caller-identity propagation by itself. Do not depend on it or automatically expose discovered operations.                                                                                                                                                         |
| MCP                     | Official SDK 1.32.1 supports stateless Streamable HTTP and pre-parsed request bodies. Use one transport/server per POST with JSON responses. Follow the [2025-11-25 transport contract](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports), including Origin checks, content negotiation and version handling. The current specification landing page redirects to 2026-07-28; that does not imply the selected SDK implements that revision. |

## Updated prior art

[Signal K issue #1867](https://github.com/SignalK/signalk-server/issues/1867) is still open. Repository and issue/PR searches found these relevant efforts; this is a search snapshot, not proof no other implementation exists.

- [VesselSense](https://github.com/VesselSense/signalk-mcp-server): standalone stdio server, package 1.0.8, last repository push reported 2025-11-26. Package declares MIT, but no root LICENSE was present in the inspected checkout. Its `isolated-vm` 5 dependency and older MCP SDK are inappropriate production dependencies for this native proof of concept. The execution engine constructs an isolate per call, with configurable memory/time limits and host references. It captures logs in an array; reviewing this code does not establish an OS security boundary, bounded total async execution, or sufficient output limits. No code was copied. Clarify licensing before future reuse.
- [sailingnaturali/signalk-mcp](https://github.com/sailingnaturali/signalk-mcp): standalone conventional MCP integration; no native AppStore factory was established in the reviewed material.
- [signalk-mcp-ops](https://github.com/eriksnijder/signalk-mcp-ops/tree/29482229240ccb2859a08db14b5e235f69e36c03): a newer native read-only diagnostics plugin, missed by the handoff. It retains admin routes and adds `X-MCP-Ops-Key`. Its documented purpose includes protection when host security is disabled; the key grants configured-prefix access without per-user ACL propagation. It overlaps with telemetry discovery, but does not satisfy this project's existing-token-only requirement. The owner subsequently chose to continue this independent plugin; no contribution to that project is planned.
- [BoatHacks/signalk-mcp-container](https://github.com/BoatHacks/signalk-mcp-container): deprecated wrapper around VesselSense and a stdio-to-HTTP bridge. Its README reports packaging, runtime and auth difficulties. It is not the chosen architecture.

## Historical sandbox investigation: superseded

The owner's 2026-10-18 scope correction limits this gateway to discovery, fetching and forwarding. Sandbox execution and Container Manager integration are outside scope. The following records the earlier investigation only; it is not an implementation plan.

At the inspected revision, Container Manager's `src/types.ts` confirms `ensureRunning`, address resolution, network attachment and resource limits. `ensureNetwork(name: string)` has no `internal` option. The reviewed `ContainerConfig` does not expose the proposed read-only-root, no-new-privileges or capability-drop policy. Its convenient reachable-port modes can share the Signal K network namespace, and Docker extra-host setup can add a host gateway. Those modes are unsuitable as the asserted boundary for untrusted code.

The earlier proposal would have required validating explicit isolation settings, including inspectable effective configuration and failure behavior on unsupported runtimes. A dedicated internal bridge plus reverse RPC still needs host/LAN egress tests under Linux Docker, rootless Podman and containerized Signal K. A network-disabled worker with runtime-managed stdin/stdout relay could avoid network egress, but no suitable persistent relay API was confirmed. Unix sockets require a narrowly scoped shared mount and permissions/lifecycle support, conflicting with the handoff's blanket no-host-mount requirement unless explicitly revised. Neither is implemented or validated.

No execution broker or sandbox is planned under the current fetch-and-forward scope.
